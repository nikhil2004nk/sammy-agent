# 2. Model Context Protocol (MCP) for Tool Execution

Date: 2026-07-20

## Status
Accepted

## Context
Jarvis needs to interact with various external tools (Gmail, GitHub, Slack) to be effective. Building native adapters for every provider directly inside the Jarvis platform leads to bloat, dependency hell, and tight coupling between the reasoning engine and external API SDKs.

## Decision
We leverage the **Model Context Protocol (MCP)** standard to decouple capabilities.
- The Jarvis platform acts as an **MCP Client**.
- External capabilities (e.g., `gmail-mcp-server`) are built as independent **MCP Servers** that run as standalone processes (communicating over stdio, SSE, etc.).
- MCP Servers are solely responsible for provider-specific logic, including managing their own OAuth token refresh lifecycles.

## Consequences
- **Positive:** Jarvis remains entirely provider-agnostic. Adding GitHub capability requires zero code changes to the core platform.
- **Positive:** Independent packages can be open-sourced or swapped out easily.
- **Positive:** Tools are automatically discovered and structured via the MCP registry.
- **Negative:** Debugging execution failures requires tracing across process boundaries (Client -> Stdio -> Server).
