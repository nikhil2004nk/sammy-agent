# 2. Model Context Protocol (MCP) for Tool Execution

Date: 2026-07-20

## Status
Accepted

## Context
Sammy needs to interact with various external tools (Gmail, GitHub, Slack) to be effective. Building native adapters for every provider directly inside the Sammy platform leads to bloat, dependency hell, and tight coupling between the reasoning engine and external API SDKs.

## Decision
We will adopt the Model Context Protocol (MCP).
- The Sammy platform acts as an **MCP Client**.
- External tools run as isolated **MCP Servers**.
- MCP Servers are solely responsible for provider-specific logic, including managing their own OAuth token refresh lifecycles.

## Consequences
- **Positive:** Sammy remains entirely provider-agnostic. Adding GitHub capability requires zero code changes to the core platform.
- **Positive:** We can use any open-source MCP server.
- **Negative:** Slightly increased latency for tool calls due to the RPC layer (stdio or HTTP/SSE).
- **Negative:** Debugging execution failures requires tracing across process boundaries (Client -> Stdio -> Server).
